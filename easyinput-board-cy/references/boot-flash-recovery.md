# BOOT、烧录与恢复

## 当前实板的唯一正确操作

### 进入下载模式

1. 保持开发板处于开机状态。
2. **短按一次 BOOT 并松开。**
3. 等待电脑出现 ESP32-S3 下载端口，再让烧录工具连接该端口。

不需要按住 BOOT，也不需要配合关机、重新上电或插拔 USB。

### 退出下载模式

1. 用板上电源开关关机。
2. 再正常开机。

不需要再次按 BOOT，也不需要寻找 RESET 按键。

## 为什么不能套用通用教程

当前板的原理图中，K2/U10 电路同时涉及 `BOOT0` 与 `RST`，因此 BOOT 不是常见开发板上单纯把 GPIO0 拉低的裸按键。用户已在 2026-08-05 对当前实板确认“一按即进、重启即退”的操作合同。开发者只依赖这个可观察行为，不自行推导或改写其内部时序。

板上没有独立、供用户操作的 `RESET/EN` 按键。文档和测试步骤不得要求用户按不存在的 Reset。

## 已作废、禁止传播的流程

- “先关机，按住 BOOT，再开机或接 USB，看到端口后松开”；
- “整个烧录过程持续按住 BOOT”；
- “按住 BOOT 的同时按 RESET”；
- “单按 BOOT 不会进入下载模式”。

这些是通用 ESP32 操作或旧资料，不适用于当前 EasyInput 开发板。

## 烧录边界

BOOT 只解决进入 ROM 下载模式，不替项目决定写入范围。烧录前仍应：

1. 识别目标端口、芯片与设备身份，避免写错板；
2. 按目标工程决定写入范围和目标分区；
3. 对会覆盖任意持久数据的操作取得明确授权；
4. 烧录完成后按“关机 → 开机”回到正常运行模式。

不要把某个现有工程的分区表或 `erase-flash` 习惯写进板级流程。

## 端口未出现时

依次检查板型、USB 数据线、供电和电脑端口列表，然后再次执行“开机状态短按并松开 BOOT”。不要未经确认退回旧的“按住上电”步骤。若重复失败，保留端口变化和串口日志，按硬件/USB 故障处理。
