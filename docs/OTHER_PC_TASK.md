# 另一台电脑开发任务：DeskMate 软件 MVP 核心

## 目标

把当前纯交互 Demo 推进为“软件端第一阶段可用版本”：数据能保存、麦克风能真实录音、核心设置会跨页面生效，同时为后续语音识别、桌面壳和硬件通信留下清晰接口。

## 必须完成

### A. 应用状态与本地持久化

1. 建立统一的应用状态层，避免每个页面各自保存互不相通的临时 state。
2. 使用带 schema 版本号的本地存储，至少持久化：
   - 历史记录；
   - 热词和替换规则；
   - 8 个按键与旋钮映射；
   - 麦克风来源；
   - 文字整理方式、外观与悬浮窗设置；
   - AI 状态到表情的映射；
   - 当前表情、表情编辑参数；
   - 动作参数和环境感知开关。
3. 提供“导出配置 JSON”“导入配置 JSON”“恢复默认设置”。
4. 导入时校验数据；格式错误不能让应用白屏，必须显示用户可理解的错误。

### B. 真实麦克风录音

1. 使用浏览器 MediaDevices API 枚举麦克风，支持选择输入设备。
2. 使用 MediaRecorder 完成真实的开始、计时、停止、取消。
3. 使用 Web Audio API 显示实时音量/波形反馈。
4. 停止后生成本地录音条目，可试听、删除；刷新后保留元数据。若音频 Blob 无法安全持久化，可使用 IndexedDB，并在代码中说明原因。
5. 未接入语音识别服务时，明确显示“录音完成，等待转写服务”，禁止伪造识别结果。
6. 处理无权限、没有麦克风、设备拔出和浏览器不支持等错误。

### C. 服务与硬件适配层

定义稳定接口，并提供 mock 实现：

- `SpeechToTextAdapter`
- `DeviceAdapter`
- `AgentStatusAdapter`
- `DesktopBridge`

页面只调用接口，不直接依赖未来的串口、USB、Tauri/Electron 或具体云 API。mock 数据要集中管理并明确标注。

统一 AI 事件模型至少包含：`idle`、`listening`、`thinking`、`working`、`waiting_user`、`completed`、`error`。切换 mock 状态时，工作台任务、表情和状态徽标必须同步更新。

### D. 质量保障

1. 为存储迁移、导入校验和 AI 状态映射补充自动化测试。
2. 保持 12 个现有路由都能打开。
3. 保持 1440×1024 主设计不出现明显布局回归，并保证 1024px 宽度下可用。
4. 运行 `npm run build`，不得有构建错误。
5. 浏览器控制台不得出现未处理异常。

## 建议目录

```text
src/
  domain/          领域模型与事件类型
  store/           应用状态、持久化、迁移
  adapters/        STT、设备、Agent、桌面桥接口及 mock
  hooks/           麦克风、录音和跨页面业务 hooks
  components/      可复用业务组件
  pages/           页面层，只组合能力
```

可以根据项目实际情况调整，但不要把所有逻辑继续堆进 `pages.jsx`。

## 验收清单

- [ ] 修改热词、按键、设置或表情映射后刷新页面，数据仍在。
- [ ] 导出配置后恢复默认，再导入配置，可以恢复原设置。
- [ ] 用户允许麦克风权限后能真实录音、看见动态音量、停止并试听。
- [ ] 用户拒绝权限时界面给出清晰说明，不崩溃。
- [ ] mock AI 状态变化会同步影响工作台任务状态与桌宠表情。
- [ ] 所有 12 个页面仍可访问。
- [ ] 自动化测试通过，`npm run build` 通过。
- [ ] 没有提交账号、Token、Wi-Fi 密码、局域网地址或私密截图。

## 明确不做

- 不接真实 ESP32 固件协议。
- 不购买或绑定具体语音识别服务。
- 不实现全局系统快捷键、系统托盘或开机启动。
- 不重做视觉设计。
- 不把 Demo 状态描述成真实硬件已连接。
