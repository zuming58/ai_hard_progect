# DeskMate 与现有 EasyInput 板子的联动状态

更新时间：2026-08-21

## 用户所说的“连通”

本阶段不是控制未来桌宠的屏幕、灯效、舵机或传感器，而是打通现有 EasyInput 板子的语音输入业务链路：

```text
按下板子语音键
  → DeskMate 显示“正在录音”并出现声波
  → 接收板子麦克风或所选电脑麦克风的音频
  → 再按一次结束
  → 语音转文字
  → 文字进入 DeskMate 历史记录
  → 按设置复制或写入当前 Windows 输入框
```

## 当前结论

这条链路目前只完成了软件侧的一部分，**还没有端到端接通**。

- DeskMate 已能调用电脑麦克风录音、显示声波、保存录音 Blob 与历史元数据。
- DeskMate 还没有桌面运行时，因此 Web 页面不能可靠监听系统全局快捷键，也不能把文字写入其他应用的当前输入框。
- DeskMate 还没有真实 STT 服务，因此录音结束后只会显示“等待转写服务”。
- EasyInput 板子的 USB HID 已被 Windows 识别，但当前 DeskMate 没有监听它发出的按键/快捷键。
- Windows 没有把 EasyInput 板子枚举成独立 USB 麦克风；原软件页面说明板子麦克风通过 2.4GHz Wi-Fi 向电脑发送音频，因此还需要确认本地网络协议。

## 本机只读检测证据

2026-08-21 在本机、板子通过 USB 集线器连接时，Windows 显示：

- USB HID：`VID 303A / PID 1006`，实例名称包含 `EASY-INPUT-V2`。
- 键盘集合：`HID\VID_303A&PID_1006&COL01`。
- 厂商自定义 HID 集合：`HID\VID_303A&PID_1006&COL03`。
- 没有发现属于 `VID 303A / PID 1006` 的 Windows 音频输入端点。
- 没有发现属于该板子的串口；本机只有系统 `COM1`，不能把它当成板子串口。

这些结果说明：

1. 通过集线器连接没有问题，Windows 已收到板子的 USB HID 接口。
2. HID 键盘接口足以让板子像键盘一样发送按键，但浏览器页面无法确认是哪一块键盘发出的普通按键。
3. `COL03` 可能是厂商自定义 HID 报告，但在没有报告描述符或协议前不得猜测写入。
4. 板子麦克风不是标准 USB Audio 设备；要复现原软件体验，必须验证其局域网音频流。

## 分链路状态

| 链路 | 当前状态 | 下一步 |
|---|---|---|
| 板子 USB/HID 被 Windows 识别 | 已确认 | 记录按键实际发出的快捷键 |
| 板子按键触发 DeskMate | 未接入 | 桌面桥监听全局快捷键/输入事件 |
| 电脑麦克风录音 | 已实现 | 在桌面壳中复测权限与设备切换 |
| 板子麦克风音频 | 未接入 | 只读观察原软件的局域网连接并形成协议报告 |
| 录音状态、声波与计时 | 已实现 | 接入板子触发事件 |
| 语音转写 | 未接入 | 实现可替换 STT Adapter 并选择真实供应商 |
| 历史记录与录音保存 | 已实现 | 接入真实转写结果 |
| 输出到当前 Windows 输入框 | 未接入 | 桌面桥实现剪贴板/安全粘贴策略 |

## 推荐实现顺序

1. 为现有 React/Vite 项目加入 Windows 桌面壳与安全的 preload/IPC 桥。
2. 先用板子现有的快捷键触发 DeskMate，并暂时使用电脑麦克风，跑通“按键—录音—历史”链路。
3. 接入真实 STT Adapter，跑通“录音—转写—历史—当前输入框”。
4. 只读观察原 EasyInput 软件与自有板子的局域网连接，确认板子麦克风流协议。
5. 协议确认后增加 `EasyInputLanAudioAdapter`，使“键盘优先”真正使用板子麦克风。

未来桌宠屏幕、灯效、舵机和传感器不属于本轮任务。

## 安全与隐私

- 只分析用户自己的板子和本机流量；不绕过认证，不上传抓包原件。
- 报告必须移除 Wi-Fi 密码、真实 IP、账号、Token、设备序列号和语音内容。
- 未知的厂商 HID 报告只允许读取描述符，禁止发送随机字节、烧录、擦除 Flash、修改分区或写 eFuse。
- 全局快捷键、剪贴板和模拟粘贴必须由用户启用，并提供明显状态和关闭入口。
