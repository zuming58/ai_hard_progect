# 开发板身份与事实优先级

## 当前开发板

本 Skill 只适用于当前 EasyInput 开发板。下面几个名称指向同一套硬件基线，不是三个需要分别维护的板型：

| 使用场景 | 名称 |
| --- | --- |
| 产品、课程和对外名称 | `EasyInput V2.0` |
| 固件板型别名 | `v2` / `V2` |
| PCB 历史丝印 | `AI Keyboard V2.1` |

不要因为这些别名而推断多套电气设计，也不要因为 PCB 丝印而加载旧版引脚。目标项目可自选内部板型标识，但必须明确映射到本页的当前硬件基线。

## 硬件基线

- SoC：`ESP32-S3R8`，封装内 8 MB、3.3 V Octal SPI PSRAM。
- Flash：外置 `W25Q128` 系列，16 MB。
- 原生 USB：ESP32-S3 USB D-/D+，板上 USB-C 接口与 D21/D22 ESD 保护。
- 无线：ESP32-S3 片上 Wi-Fi/BLE，板载 PCB 天线。
- 人机部件：8 个独立主按键、1 个带按压的旋转编码器、5 颗串联 WS2812、1 颗独立绿色状态灯、I2S 麦克风和 I2S 功放/扬声器接口。
- 板上没有供用户操作的独立 `RESET/EN` 按键。BOOT 是一键下载电路，不应按普通裸 GPIO0 按键理解。

## 事实分层

开发前先判断信息属于哪一层：

1. **板级事实**：器件、连线、GPIO、有效电平、电源时序、BOOT 操作。所有项目必须遵守。
2. **项目策略**：按键动作、协议、分区、USB 身份、NVS、功耗策略、音频产品逻辑。只能在对应目标项目中使用。
3. **运行或发布状态**：固件版本号、当前 build、某次 HIL 结果。会持续变化，不得写成开发板身份。

例如 `S1=GPIO2` 是板级事实；“S1 触发某个业务动作”是项目策略；某个版本号是运行或发布状态。后两者都不能反推硬件。

## 冲突时的优先级

从高到低使用：

1. 用户对当前实板的明确确认，尤其是最新操作行为。
2. 可追溯的当前批次 ECAD/BOM/装配资料与板级专项测试。
3. 随 Skill 打包的两页原理图和 PCB 正反面图。
4. 本 Skill 的 `board-contract.json`；它是上述证据的规范化机器副本，若与原始证据冲突则必须修订，不能自证正确。
5. 用户明确指定的目标项目声明；它只能描述项目选择，不能覆盖物理连线。
6. 历史迁移文档、旧版本代码、临时归档和网络上的通用 ESP32 教程。

当前已知的重要冲突是 BOOT 流程：2026-08-05 硬件负责人确认的当前实板行为是“开机状态短按并松开 BOOT 即进入下载模式；关机再开机即退出”。旧资料中的“关机后按住 BOOT 再上电”已作废。

## 不属于板级合同的内容

- ESP-IDF 具体版本；
- Flash 分区表和 NVS 地址；
- PSRAM 的 allocator 策略；
- USB VID/PID、设备名和协议；
- S1～S8 的产品动作；
- BLE、Wi-Fi、模型、音频流或 App 协议；
- 烧录整片、App-only 或保留 NVS 等项目发布策略。

这些内容必须由目标工程自行定义。除非用户明确要求移植，否则不要搜索或读取其他应用工程来填充它们。
