# EasyInput 当前开发板知识与 AI 上下文

## 定位

把本 Skill 当作当前 EasyInput 开发板的权威知识包和上下文来源。它回答“这块板是什么、物理连了什么、哪些边界不能破坏、哪些内容仍未知”，让用户能够查询开发板资料，也让正在执行其他开发任务的 AI 快速读对硬件。

本 Skill 的职责在交付开发板硬件事实、证据边界和安全约束时结束。用户另行要求开发时，Agent 可以依据总体任务继续创建或修改代码，但该授权与实现流程来自用户请求、目标项目约定及其他适用 Skill，不来自本 Skill。不要因为调用本 Skill 就自行创建工程、改代码、构建、烧录或监视串口。

除非用户明确把某个工程指定为资料核对对象，否则不要读取、套用或推荐工作区里的其他应用工程；它们不是开发板知识来源、示例模板或默认实现。

当前三个名称指向同一块硬件基线：

- 产品/课程名称：`EasyInput V2.0`
- 固件板型别名：`v2`
- PCB 丝印：`AI Keyboard V2.1`

这些名称不能用来推断三套不同的电气设计。目标项目可以自选内部板型标识，但必须明确映射到这套硬件基线；结构件 V25/V26 也不代表新的电气板版本。

## 先执行这套上下文工作流

1. **确认需要哪部分开发板信息**
   - 判断用户是在直接查询开发板资料，还是让 AI 为另一个开发、诊断或评审任务加载硬件上下文。
   - 只围绕用户提到或目标任务实际涉及的资源取数；板上存在某资源不等于本次必须讨论或初始化它。
   - 如果用户只询问开发板资料而未指定工程，就停留在 Skill 自带的 references 与 assets，不到工作区搜索项目。
   - 如果用户明确要求核对某个项目，只读取该项目中与板型、引脚或板级约束直接相关的声明；不借机扩展为开发或重构任务。

2. **按任务读取事实**
   - 身份、版本别名和证据优先级：读 `references/identity-and-authority.md`。
   - GPIO、方向、有效电平或 UART：读 `references/pinout.md`。
   - BOOT、下载、恢复或端口问题：必须读 `references/boot-flash-recovery.md`。
   - GPIO8、电池、LED、USB、音频、唤醒或睡眠：读 `references/power-and-peripherals.md`。
   - 需要区分板级事实与项目自定义项：读 `references/project-boundaries.md`。
   - BOM、DNP、Gerber、历史冲突或批次风险：读 `references/known-gaps-and-errata.md`。
   - 需要追溯原文件、提交或快照时：读 `references/source-map.md` 和 `references/source-manifest.json`。

3. **整理可交付的开发板上下文**
   - 硬件层只保存 SoC、存储、GPIO、电气方向、有效电平、共享电源、板载外设和物理操作。
   - 项目层保存按键动作、消抖参数、编码器方向与交互、协议、分区、音频格式与控制器、休眠策略、ESP-IDF 版本和 PSRAM 使用方式。
   - 输出时给出本次相关的板型身份、GPIO/方向/有效电平、安全边界、已知未知项和来源；把项目层内容明确标为“由目标项目决定”。
   - 不替目标项目选择策略，也不从其他工程推断默认值。

4. **按需做只读声明核对**
   - 只有用户要求核对明确项目时，才运行 `scripts/check_board_baseline.py`；以 `--help` 显示的参数为准。
   - `FAIL` 表示与当前板级合同冲突，先修正或拿到新的硬件证据；`WARN` 表示静态扫描无法确认或发现潜在风险，不能自动改写成失败。
   - 普通头文件保护、未选构建分支和不被识别的代码形态都可能让声明退出 PASS/FAIL；出现 `BUILD_BRANCH_UNSELECTED` 或 `PIN_DECLARATIONS_NOT_FOUND` 时，必须说明对应内容未被验证。
   - 脚本只是启发式只读扫描器。退出码 `0` 只表示没有发现已建模的 `FAIL`，不证明原理图、电气安全、构建图、装配状态或真机行为。

5. **回答或交还上下文**
   - 直接查询时，只回答有证据的开发板硬件事实，同时标明未知项、被取代说法和必要安全边界。
   - 作为开发上下文时，把整理结果交还给总体开发任务；不在本 Skill 内规定代码结构、组件选择、业务行为、构建命令或发布流程。
   - 总体任务若涉及 ESP-IDF 环境、build、flash、monitor 或设备验身，再由 Agent 使用 `esp-idf-cy` 或其他适用工具。本 Skill 只提供当前板专属事实，不构成执行或写入授权。
   - 必须区分资料已确认、静态声明未见冲突、构建通过、烧录通过、应用日志通过和用户观察到物理现象。没有相应证据时不要升级结论。

## 当前板的不可破坏合同

### BOOT 与正常启动

- 开机状态下，**短按并松开一次 BOOT** 即进入下载模式。
- 不需要按住 BOOT，不需要配合重新上电，不使用通用“按住 BOOT 再上电”步骤。
- 退出下载模式只需关机一次，再重新开机；恢复时不要再次按 BOOT。
- 板上没有独立的用户 RESET/EN 按键。
- 以上是硬件负责人于 2026-08-05 对当前实板的确认，覆盖仓库旧文档里的传统 ESP32 手动 strap 流程。若实物不符合，先检查板型、批次或硬件异常，不要静默退回旧操作。

### 关键资源

- S1–S8 固定为 GPIO `2, 47, 38, 41, 1, 6, 7, 48`；GPIO0 不是 S5。
- 编码器 A/B/按压固定为 GPIO `17/16/18`；A/B 是正交相位，不是两个普通按住键。
- GPIO8 是高有效的 LED/MIC/SPK 共享电源域。先锁存下游安全状态，拉高并确认电源稳定后才能使用这些外设；当前资料不能证明统一的最短稳定时间，目标项目必须依据器件规格或测量完成资格确认。何时在清醒状态关断由目标项目决定，但必须先让所有共享消费者停止并恢复安全引脚状态。
- 5 颗 WS2812 串联共用 GPIO12，不是五个独立 GPIO。
- 原生 USB 使用 GPIO19/20；麦克风使用 GPIO9/10/11；扬声器使用 GPIO14/13/15。
- KEY_WAKE GPIO21 只表示聚合唤醒，唤醒后重扫各输入才能确定来源。

完整映射、有效电平和限制只在 `references/pinout.md` 与 `references/power-and-peripherals.md` 维护，不在应用代码或回答中凭记忆补齐。

## 事实冲突处理

按以下顺序处理当前板事实，且记录被取代关系：

1. 硬件负责人明确确认的当前实板行为或可复现 HIL 证据。
2. 可追溯的当前批次 ECAD/BOM/装配资料与板级专项测试。
3. 随 Skill 打包的原理图、PCB 快照与硬件说明。
4. 本 Skill 的 `board-contract.json` 及其合同测试；它是前述证据的规范化机器副本，若与原始证据冲突则必须修订，不能自证正确。
5. 用户明确指定的目标项目声明；它只能描述项目选择，不能覆盖物理连线。
6. 历史迁移文档、旧版本代码、临时归档和网络上的通用 ESP32 教程。

低优先级材料只能提供线索，不能覆盖更高优先级事实。发现冲突时指出来源、采用哪一条及原因；没有足够证据时保留 `UNKNOWN`，不要做“最像 ESP32 常规做法”的猜测。

## 项目边界

- 本 Skill 不创建或初始化 ESP-IDF 工程，不编写或修改业务代码，不选择项目架构，也不负责 build、flash、monitor 或 HIL。
- 在更大的开发任务中调用本 Skill，只表示 Agent 应读取并遵守板级事实；开发动作是否执行仍由用户请求、项目约定和其他适用 Skill 决定。
- 本 Skill 不定义 S1～S8 的动作、编码器方向/步进/长短按、LED 语义、USB 协议身份、分区、NVS、OTA、联网、音频格式或睡眠产品逻辑。
- 物理 8 MB PSRAM 与 16 MB Flash 是板级事实；分配策略、分区 CSV 和具体 ESP-IDF 版本是目标项目合同。
- 既有应用即使使用同一块板，也不能成为开发板知识或其他项目的隐式模板。只有用户明确要求核对或移植某一应用时，才可把该应用作为独立输入读取，并仍以本 Skill 的硬件合同为上限。
- 若目标项目声明与板级事实冲突，报告冲突并交还总体任务处理；若新实板证据反驳合同，暂停引用该事实并按变更门更新本 Skill。

## 完成标准

完成一次开发板资料回答或 AI 上下文加载前，确认：

- 板型身份没有被误判成 V2/V2.1 两套不同电气设计。
- 本次涉及的 GPIO、有效电平、外设方向和限制可追溯到当前 reference。
- GPIO8、GPIO0、GPIO19/20 等相关硬护栏已随上下文交付。
- 板级事实、目标项目策略和仍未知内容被清楚区分。
- 静态扫描、构建、烧录、日志和真机证据没有互相冒充。
- 新发现的硬件事实附来源、日期和验证方式；未知项仍明确为未知。
- 没有把调用本 Skill 当成创建项目、改代码、构建或写入设备的授权。

## 禁止事项

- 不把“按住 BOOT + 上电”教给当前板用户。
- 不把 GPIO0 写成 S5、普通按键或应用复用脚。
- 不把 GPIO8 当作只控制灯带的开关，也不把其他工程中的延时值当成已证明的硬件最小值。
- 不从历史日志中取第一条 GPIO 命中作为当前真值。
- 不硬编码 `/dev/cu.usbmodem101` 或用端口名代替设备身份。
- 不因截图中出现料号就声称已有最终 BOM、DNP 或量产验收。
- 不主动搜索、引用或继承任何既有应用工程的按键动作、命名、协议、分区、依赖版本、电源策略或实现架构。
- 不把本 Skill 描述成项目脚手架、固件生成器、构建器、烧录器或完整开发板 SDK。
