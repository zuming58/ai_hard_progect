# EasyInput V2.0 统一知识基线

> 基线日期：2026-08-19
> 本文是当前资料的消化结论，不替代原理图、源码和真机测试。

## 一句话定位

EasyInput V2.0 是以键盘为具象形态的 ESP32-S3 AI 硬件开发板。它集成输入、灯光、音频、电池、USB 和无线能力，训练营用它教授“需求表达 -> AI 修改 -> 构建 -> 烧录 -> 真机验证 -> 排错恢复”的完整方法，而不是要求零基础学员先手写全部代码。

## 身份归一

- 产品/课程名：`EasyInput V2.0`；
- 固件板型别名：`v2` / `V2`；
- PCB 丝印：`AI Keyboard V2.1`；
- 结构件 V25/V26 不表示新的电气版本。

以上名称当前指向同一硬件基线，不能据此推导出三套 pinout。

## 核心硬件

- 主控：ESP32-S3R8，双核最高 240 MHz，芯片内 8 MB PSRAM；
- 外置 Flash：16 MB；
- 输入：8 个独立低有效机械按键、一个旋转编码器及按压；
- 输出：5 颗串联 WS2812、独立绿色状态灯、MAX98357A 扬声器路径；
- 音频输入：I2S 数字麦克风；
- 通信：Wi-Fi、BLE、ESP32-S3 原生 USB；
- 供电：USB-C、锂电池、充电及电池端电压采样电路；
- 调试：J4 3.3 V UART0 焊盘。

## 当前板专用 BOOT 合同

进入下载模式：

1. 保持开发板开机；
2. 短按一次 BOOT 并松开；
3. 等待 ESP32-S3 下载端口出现。

退出下载模式：关机一次，再正常开机。板上没有供用户操作的独立 RESET/EN 按键。

这是 2026-08-05 对当前实板确认的行为，覆盖“按住 BOOT 再上电”“按住 BOOT 同时按 RESET”等通用教程。`esp-idf-cy` 中的 BOOT+RESET/断电说明是面向未知通用开发板的兜底流程；处理 EasyInput 当前板时必须先采用本板专用合同。

BOOT 只负责进入 ROM 下载模式，不代表已经授权擦除或写入固件。

## GPIO8 共享电源域

GPIO8 不是单独的灯带开关，它共同控制 LED、麦克风和扬声器所在电源域。安全冷启动原则：

1. 先将 GPIO8 输出锁存为低；
2. 将 GPIO9/10/12/13/14/15 等下游命令输出预置为安全低电平，GPIO11 保持禁用/浮空；
3. GPIO8 拉高；
4. 等电源稳定后再初始化 LED、麦克风和扬声器。

目前没有跨器件、项目和板批次均成立的固定最短等待毫秒数。该值必须由目标固件依据数据手册或实板测量确定。运行中关断前要先停止三个消费者、清空在途访问并恢复安全引脚状态。发送 RGB 全黑帧只表示灯灭，不表示共享电源已经关闭。

## 电池与电量边界

- 测电压前拉高 GPIO5，再由 GPIO4 读取约为 VBAT/2 的电压；
- 板上没有专用 fuel gauge；
- 单次端电压无法直接转换为准确剩余百分比，算法需结合负载、温度、电池特性和实测曲线校准；
- 只有 GPIO40 表明外部供电存在时，GPIO39 的充电/充满状态才有解释意义。

## 两类“AI/语音”不能混为一谈

### 日常 EasyInput 语音输入

现有开箱资料描述的是电脑端 EasyInput App 工作流：S1 触发语音输入，首次建议使用电脑麦克风；板载麦克风要完成 Wi-Fi 配置，默认不作为系统蓝牙麦克风出现。这套产品链路是否调用云端、具体服务端协议与当前版本实现，必须以 App/固件源码、网络观测或官方明确说明为准。

### 实验性端侧中文问答模型

课程资料另有一套已在真板跑通的垂直问答实验：7,834,112 个参数、Q4 权重和 int8 激活、完整模型包 4,338,384 字节（约 4.14 MiB），围绕 55 条原子事实构造 5,920 条训练记录，可离线逐 token 回答 EasyInput 相关问题。公开资料称完整回答约 1.5-2.25 秒，1,146 条验证中部署近似路径正确 996 条。

它是任务边界很窄的定制模型，不等同于开放世界大模型，也不能据此断言日常语音转文字同样完全离线。现有工作区未包含其训练代码、C 运行时、模型包或可烧录固件，因此目前只能引用公开工程记录，不能在本机复现这些指标。

## 课程与作业上下文

课程规划为 8 节正课、4 次自习室和加餐/作品环节，核心路径是：认识 AI 硬件、烧录、功能改造、实体功能键、Agent 状态灯、声音转文字、故障恢复、迁移新项目。

当前目录只有第 1 课讲义、总结和会议纪要。第 1 课作业为开放题，可选：

1. 自己理解的 AI 硬件；
2. 基于 EasyInput V2.0 的功能改造设想；
3. 如何用 AI 辅助硬件开发。

会议纪要注明详细要求以后续主文档为准。因此开始代写前，应先接收最新作业题面、字数、提交格式、截止时间和是否要求个人真实经历；不得仅凭旧纪要虚构要求。

## 后续共创的工程原则

- 先定义用户可观察的成功标准，再改代码；
- 优先在课程提供且已跑通的基线工程上做最小修改；
- 修改前确认目标项目、板型、ESP-IDF 精确版本、分区和恢复方案；
- 构建前运行板级静态核对；静态 PASS 不等于构建或真机 PASS；
- 烧录前用芯片型号和 fresh MAC 验身，并让用户明确确认目标设备；
- 烧录后恢复正常启动，以应用专用健康日志和真实外设现象收口；
- 每次保留目标、修改、构建、写入、真机现象五类记录，便于恢复和写作业。

## 志愿者答疑口径

回答时把内容分成四类：

- 已确认：可由当前板合同、实测或权威原件支持；
- 当前版本行为：某 App/固件版本的现象，不提升为永久硬件事实；
- 项目决定：按键动作、采样率、USB 身份、睡眠策略等由目标项目定义；
- 待确认：没有源码、实测或明确答复时如实保留。

特别拦截：S5=GPIO0、GPIO8 只管灯、5 颗灯占 5 个 GPIO、KEY_WAKE 能识别具体键、EasyInput 当前板需按住 BOOT 上电、烧录退出 0 等于应用运行。
