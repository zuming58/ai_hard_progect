## 已发现的冲突与风险

1. `07-综合技术知识库` 中仍有“按住 BOOT -> RESET”的通用 ESP32 流程。它不能用于 EasyInput 当前板；当前板使用开机状态短按并松开 BOOT。
2. `08-群内答疑FAQ库` 把“开发板自带的语音识别”直接回答为 783 万参数本地模型，表述过宽。端侧问答实验与日常 EasyInput 语音输入产品链路必须分开。
3. 根目录 `00-资料索引.md` 仍写旧路径 `F:/Hermes/AI硬件训练营/`，当前实际路径为 `F:/Codex/ai hardware/`。
4. `easyinput-board-cy` 工作树已有两张原始原理图 PNG 缺失：`assets/easyinput-v2-schematic-page-1.png`、`page-2.png`。品牌展示版仍在，但仓库状态不是干净基线。未擅自恢复。
5. `easyinput-board-cy` 的板级 checker 测试 11 项通过；Skill 合同测试因许可证文本校验失败而中止。当前 `git diff` 未显示 LICENSE 文本改动，需之后在干净仓库/对应平台复核编码或测试假设。
6. `esp-idf-cy` 的 Python 测试在 Windows 上 12 项通过、1 项跳过，串口监视测试因依赖 POSIX `termios` 无法导入。这个结果是平台限制，不是串口功能真机验证。
7. 当前工作区路径包含空格 `ai hardware`，而 ESP-IDF 官方工程/IDF 路径不支持空格。后续真实构建应使用无空格的受管工作副本或经确认迁移，不能直接假设此路径可编译。
