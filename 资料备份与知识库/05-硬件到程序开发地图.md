# EasyInput V2.0：从硬件到程序的开发地图

> 目标：把“板上有什么”“电气上怎样连”“固件里怎样用”“怎样证明真机生效”串成同一条链。

## 一、先说明当前证据边界

当前已经具备：原理图/PCB 快照、实拍、机器可读板级合同、完整 GPIO 表、ESP-IDF 工作流和部分驱动示意。

当前尚未具备：课程产品固件源码、组件依赖、分区表、烧录包、App 协议和运行日志。因此本文可以给出正确的板级信号路径与推荐软件分层，但不能声称已经掌握课程固件内部的函数、任务、消息队列或协议实现。拿到源码后需要补做“实际代码地图”。

## 二、建议的软件分层

```text
应用行为
  按键动作 / Agent 状态 / 语音流程 / 电量显示
        |
服务层
  input_service / led_service / audio_service / power_service / usb_or_network
        |
板级驱动层
  keys / encoder / ws2812 / status_led / mic_i2s / speaker_i2s / battery / boot-info
        |
board_config / board_pins
  GPIO、有效电平、共享电源、保留资源
        |
ESP-IDF 驱动
  GPIO / RMT或led_strip / I2S / ADC / USB / sleep / UART
        |
EasyInput V2.0 硬件
```

`board_config` 应当是唯一的 pin 映射入口，避免在业务代码里散落魔法数字。硬件事实放板级层，按键触发什么动作、灯显示什么状态放应用层。

## 三、器件/信号/GPIO/程序/验证对应表

| 硬件对象 | 电气信号与 GPIO | 程序入口 | 必须验证的真机现象 |
| --- | --- | --- | --- |
| S1-S8 | GPIO 2/47/38/41/1/6/7/48，低有效 | GPIO 输入+上拉；轮询或中断；软件消抖 | 单击、多键、长按/抖动是否符合项目定义 |
| 编码器 | A=17、B=16、按压=18 | A/B 状态机、PCNT 或中断；按压同普通低有效键 | 顺/逆时针不丢步，按压不与旋转误触 |
| KEY_WAKE | GPIO21，二极管 OR，低有效 | 睡眠唤醒源；唤醒后重扫独立输入 | 只能证明有输入，不能直接报告具体键 |
| 5 颗 WS2812 | PWR_EN=8，DIN=12，5 像素 GRB | 先安全开共享电源，再用 RMT/`led_strip` 发帧 | 颜色顺序、像素顺序、亮度和上电无乱闪 |
| 绿色状态灯 | GPIO42，高有效/PWM | GPIO 或 LEDC PWM | 高低电平/占空比与预期一致 |
| 数字麦克风 | PWR_EN=8；BCLK=9、WS=10、DIN=11 | I2S RX；采样率/位宽/slot 属项目配置 | 有效 PCM、无持续饱和、噪声和声道正确 |
| 扬声器路径 | PWR_EN=8；BCLK=14、WS=13、DOUT=15 | I2S TX 到 MAX98357A | 提示音能播放、无爆音、音量/格式正确 |
| 电池采样 | EN=5、ADC=4（ADC1_CH3，约 VBAT/2） | 开分压->等待稳定->ADC 多次采样->校准->关分压 | 读数随电源/负载合理变化，不冒充精确电量 |
| 供电/充电 | VIN=40（低=有外部供电）；CHRG=39 | 先判断 VIN，再解释 CHRG | USB 插拔、充电中、充满状态真值表正确 |
| 原生 USB | D-/D+=19/20 | TinyUSB/USB Serial-JTAG/项目协议 | 枚举身份、重枚举、传输和恢复符合项目 |
| UART0 | RX=44、TX=43，J4 3.3V | 日志/调试串口 | 波特率正确，TX/RX 交叉，共地，不接 5V |
| BOOT | GPIO0 专用电路 | 不作为产品键；用于 ROM 下载入口 | 开机短按松开进下载；关机再开机退出 |
| Flash/PSRAM | GPIO26-37 板载占用 | 存储/内存由 SoC/项目配置管理 | 绝不当普通 GPIO 复用 |

## 四、关键硬件信号路径

### 按键

```text
手按轴体 -> Sx 触点接地 -> 对应 GPIO 由 1 变 0
                         -> 同时经二极管汇总到 KEY_WAKE
固件读取独立 GPIO -> 消抖/事件 -> 应用动作
```

主键不是矩阵键盘，因此可以独立读、多键同时检测。`KEY_WAKE` 是辅助唤醒汇总，不替代独立 GPIO。

### RGB 灯

```text
GPIO8 -> 共享电源域稳定
GPIO12 -> D1 -> D2 -> D3 -> D4 -> D5
每个 WS2812 吃掉自己的一个 GRB 像素，再转发剩余数据
```

灯的电源和数据是两件事。发黑帧不等于关闭 GPIO8；关闭 GPIO8 又会同时影响麦克风和扬声器。

### 麦克风

```text
声音 -> 数字麦克风
GPIO9 BCLK + GPIO10 WS 由 ESP32 输出时钟
麦克风 DATA -> GPIO11 -> I2S RX -> PCM 缓冲 -> 语音/录音业务
```

板级资料只固定物理信号，不固定 I2S0/I2S1、采样率、位宽、声道、DMA 缓冲或识别服务。

### 扬声器

```text
PCM/提示音 -> I2S TX
GPIO14 BCLK + GPIO13 WS + GPIO15 DATA
-> MAX98357A 路径 -> J3/SPK -> 扬声器
```

GPIO15 是数字音频数据，不能直接推动喇叭。

### 电池

```text
GPIO5 拉高 -> 打开分压采样通路
VBAT/约2 -> GPIO4 ADC -> 校准得到端电压
GPIO5 拉低 -> 减少分压长期耗电
```

端电压不是精确剩余容量。若产品需要百分比，必须做电池曲线、负载和温度校准。

## 五、共享电源状态机

建议不要让 LED、麦克风和扬声器各自直接控制 GPIO8，而是由统一 `power_service` 维护使用者引用或状态机：

```text
OFF
 -> 预置 9/10/12/13/14/15 为安全低，11 禁用/浮空
 -> GPIO8=1
 -> WAIT_STABLE（项目测量/器件依据）
 -> READY
 -> LED/MIC/SPK 分别 acquire/release
 -> 所有消费者停止且无在途访问
 -> 恢复安全引脚
 -> GPIO8=0
 -> OFF
```

具体是引用计数、事件组还是服务任务由目标工程决定。关键合同是不能让一个模块在其他模块工作时误关共享电源。

## 六、从零初始化的推荐顺序

1. 核对板型与集中式 GPIO 常量；
2. GPIO8 初始保持低，预置共享外设信号安全状态；
3. 初始化主按键、编码器和必要的唤醒输入；
4. 拉高 GPIO8，等待经过项目验证的稳定条件；
5. 初始化 GPIO12/5 像素/GRB 的 WS2812；
6. 按需初始化麦克风 I2S RX 和扬声器 I2S TX；
7. 初始化电池与供电状态检测；
8. 最后配置 USB、网络、睡眠和应用行为。

## 八、构建与烧录流程

```text
读取项目声明
-> 选择/验证精确 ESP-IDF 环境
-> 只读板级基线扫描
-> build
-> 识别芯片型号与 fresh MAC
-> 向用户说明目标设备和写入范围
-> 用户明确确认
-> flash
-> 按 EasyInput 专用方式恢复正常启动
-> 采集应用专用健康日志
-> 检查真实按键/灯/音频/USB现象
```

工作区路径 `F:/Codex/ai hardware` 含空格，不适合作为 ESP-IDF 实际构建路径。后续构建应在无空格位置建立受管工作副本，或经用户确认迁移项目；不能只靠 shell 引号解决 ESP-IDF 上游限制。

## 九、烧录安全红线

- 未读芯片型号和 fresh MAC，不烧；
- 未让用户确认具体设备和写入范围，不烧；
- 不自动擦除整片 Flash；
- 不把端口名当永久设备身份；
- flash 退出 0 只说明写入命令完成，不说明应用已运行；
- 恢复正常启动时不再次按 BOOT；
- 只有命中应用健康标志并通过真实功能验证，才报告完成。
