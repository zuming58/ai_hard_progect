## 一句话总结

一块只有 **8 MB PSRAM、16 MB Flash** 的 **ESP32-S3**，通过从随机参数开始训练的 **783万参数** 小模型，实现了 **离线中文问答**——从知识整理、训练、量化到C语言板端运行的完整链路。

---

## 核心数据速览

| 指标 | 数值 |
|------|------|
| 可训练参数 | **783万**（7,834,112） |
| 完整板端模型包大小 | **4.14 MiB** |
| 真板生成完整回答 | **1.5–2.25 秒** |
| 芯片 | ESP32-S3R8，8 MB PSRAM，16 MB Flash |
| 运行频率 | CPU 240 MHz，双核并行 |
| 首个token延迟 | 约 123–473 ms |
| PSRAM余量（模型初始化后） | 约 5.42 MB |
| 质量检查 | 41项通过34项 |

## 开发板：EasyInput V2.0

**正面部件**：电源、USB-C、8个机械按键、旋钮、RGB、麦克风孔、BOOT、状态灯、调试触点、固定柱。

**交互方式**：USB真板问答 + 本地网页界面均可使用。电脑只负责传输与显示，推理全在板上完成。

## 完整工程链路（10个章节）

### 01 先看结果：模型已经在真板上回答中文问题

- 用户在本地网页输入中文问题 → 通过USB发送到开发板
- 板上Tokenizer把文字转成数字 → 模型逐token生成答案
- 通过USB把结果传回网页显示
- 电脑不保存答案表，也不代替板子做推理

**当前状态**：开发验证版本，41项质量检查通过34项。剩余7项集中在：
- 少量问题的语义分流
- 量化差异
- 答案结束稳定性

### 02 小芯片上的模型，先从边界开始

**端侧模型**：直接运行在设备一侧，不依赖云端，可离线工作，响应路径短，数据不离开设备。

**关键思路**：不是把大模型尽量压小，而是先把"它需要解决什么问题"说清楚。模型大小、数据组织、训练方法和部署方式，都要围绕这个边界共同设计。

**任务边界**：中文单轮垂直问答，只围绕EasyInput开发板回答问题，不承担开放世界聊天。

**开始前要回答的三个问题**：
1. 这块设备必须知道哪些事实？
2. 用户可能用哪些方式询问这些事实？
3. 哪些问题应该正常回答，哪些应该要求澄清或明确超出范围？

### 03 把产品知识变成可以训练的数据

**原子事实**：一条尽量只表达一件事、能够单独检查对错的知识（如某个接口的用途、某个操作的步骤）。

**数据组织方式**：每条事实 → 规范答案 → 扩展多种真实问法

| 数据组成 | 数量 | 作用 |
|----------|------|------|
| 基础问答 | 4,664条 | 覆盖55条原子事实及其常见问法 |
| 补充问法 | 608条 | 补足更自然、更口语化的表达 |
| 语义对照数据 | 648条 | 帮助模型区分看起来相似、答案却不同的问题 |
| **合计** | **5,920条** | 围绕55条可靠事实展开 |

### 04 中文怎样变成模型能处理的数字

**Tokenizer**：把文字切成最小处理单位（token）并映射成编号的工具。

流程：
1. 输入文字 → Tokenizer切成token
2. 每个token转成整数ID → 模型计算
3. 模型生成新ID → Tokenizer还原成中文

**关键要求**：Python训练程序和C语言板端运行时必须得到完全相同的token ID（确定性中文切分规则）。

**两套词表**：
- 输入词表：**6,400个token**（覆盖更多可能问法）
- 输出词表：**4,096个token**（只保留答案真正需要的内容，减少计算和权重）
- 输出token会映射回输入词表，让已生成内容可继续参与预测

### 05 一个783万参数的小模型长什么样

**架构**：Decoder-only Transformer（按顺序一个token接一个token生成文本）

| 结构项 | 当前设置 |
|--------|----------|
| 输入词表 / 输出词表 | 6,400 / 4,096 |
| 隐藏维度 | 128 |
| Transformer层数 | 6层 |
| 注意力头数 | 4头 |
| 前馈网络维度 | 384 |
| PLE维度 | 128 |
| 上下文 / 最长答案 | 128 / 32 token |
| 参数总量 | 7,834,112 |

**关键技术**：
- **注意力机制**：帮助模型判断问题中哪些token更重要
- **前馈网络**：进一步变换和组合信息
- **RoPE**：表示token在句子中的相对位置
- **SwiGLU**：提升有限参数下的表达能力
- **PLE（Per-Layer Embeddings）**：每一层自己的辅助记忆表。前面的层更关注文字和局部结构，后面的层更关注答案选择与生成

### 06 模型怎样从随机参数学会回答

**训练起点**：随机初始化，不加载外部预训练权重。7,834,112个参数最初都是随机数。

**训练样本组织**："问题 + 答案"的token序列，加入开始和结束特殊token。只在答案区域计算误差（不要求模型复述问题）。

**Teacher Forcing**：预测下一个token时，给模型看到前面正确的答案token，让学习更稳定。

**训练流程**：预测 → 计算损失 → 反向传播 → AdamW优化器更新参数 → 重复

| 训练设置 | 当前数值 |
|----------|----------|
| 训练记录 | 5,920条 |
| Batch size | 32 |
| 训练轮数 | 7轮，每轮185 step |
| 参数更新次数 | 1,295次 |
| 学习率 / 梯度裁剪 | 0.001 / 1.0 |
| 训练环境 | Mac上的PyTorch + Apple MPS |

**Checkpoint选择**：每轮保存一份快照，用同一套评测选最优，不直接用最后一轮。

### 07 为什么量化必须从训练阶段开始

**量化的作用**：用更少的位数表达权重和中间数值。

- FP32权重约需 **29.9 MiB**（超过板子可用空间）
- 当前板端使用 **Q4权重**（约4位/权重）+ **int8激活**
- 权重主体压缩到约 **3.86 MiB**
- 完整模型包（含Tokenizer、词表、形状信息、校验信息）：**4.14 MiB**

**量化感知训练**：训练时同时观察三条数值路径
1. **高精度路径**（FP32）：观察模型本身是否学会
2. **Q4权重路径**：让模型提前适应低比特误差
3. **部署近似路径**（Q4权重+int8激活）：尽量靠近板端计算

**安全间隔**：正确答案与错误答案之间的分数间隔目标设为0.5，避免量化误差导致结果翻转。

### 08 怎样让模型分清相似问题，并证明它真的学会

**六种语义角色**：身份、能力、需要澄清、超出范围、当前开发板事实、日常问候。每种覆盖4种表达风格（直接、委婉、口语化、带上下文）。

**分叉点检查**：找到能唯一识别某个答案的最短前缀，重点检查模型在这个"分叉点"上是否足够确定。

**评测数据分离**：

| 数据集合 | 它回答的问题 |
|----------|--------------|
| 训练数据 | 模型怎样更新参数 |
| 选择集（480条） | 七轮训练中，哪一轮更值得继续检查 |
| 独立审计集（480条） | 模型是否只适应了选择集 |
| 公开验证集（1,146条） | 最终统一观察完整回答、量化一致性和语义分组表现 |

**当前成绩**（1,146条公开验证）：
- 高精度路径：正确1,001条
- Q4路径：正确996条
- 部署近似路径：正确996条

**剩余问题**：少量身份与歧义问题的分流、个别量化差异、答案结束标记稳定性、部分数据组无法同时达标。

### 09 从PyTorch到ESP32，中间还缺一整条工程链

**完整链路**：产品知识与问答数据 → Tokenizer与模型训练 → Q4量化与模型包 → ESP32 C语言运行时 → USB逐token返回 → 本地网页显示

**四大关键组件**：

1. **模型包**：完整资产包，包含Tokenizer、输出词表映射、Q4权重、张量形状、SHA-256身份校验。训练、导出、固件、运行时四个环节核对一致才能工作。

2. **C语言运行时**：负责中文Tokenizer、模型包验证、Q4矩阵计算、int8激活、Transformer前向计算、KV cache、逐token生成、结束判断、UTF-8安全输出。
   - **KV cache**：保存前面token已算过的注意力结果，避免生成每个新token时全部重算。

3. **内存分工**：
   - Flash：保存大量只读权重，通过内存映射直接访问
   - PSRAM：中间状态和较大临时缓冲
   - 内部SRAM：当前计算热点、控制结构、小型高频缓冲

4. **固件与网页**：
   - 固件：装载模型、管理内存、接收USB文本、调用运行时
   - 电脑端：只转发问题、显示逐token结果与设备状态，不含模型/Tokenizer/固定答案表/云端逻辑

### 10 这套方法还能用在哪里

**迁移时需要重新设计的四部分**：
1. 知识边界：设备必须知道什么，又明确不处理什么
2. 训练数据：怎样把可靠事实扩展成真实问法、语义对照和可检查答案
3. 模型预算：根据Flash、PSRAM、速度和任务复杂度决定词表、层数、宽度和上下文
4. 部署链路：让Python、导出工具、C语言运行时、固件和真板测试遵守同一套格式与数值规则

**可复用的完整闭环**：先限定需求 → 整理知识 → 用可检查的数据从随机参数开始训练 → 训练阶段考虑量化 → 用相互隔离的数据评测 → 同一套Tokenizer、模型和数值规则搬到芯片上验证。

> **小芯片上的模型能力，最终由任务边界、数据、模型结构、训练目标和部署环境共同决定。**
