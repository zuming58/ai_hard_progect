## 一、这篇文档到底讲什么（一句话版）

**8 MB PSRAM、16 MB Flash 的 ESP32-S3，能离线运行一个 783 万参数的中文问答模型——4.14 MiB 模型包、真板 1.5–2.25 秒出完整答案。** 这是从零训练到真板跑通的完整工程链路。

## 三、五阶段工程链路（讲义的"工程思维"）

```
产品知识与问答数据
   ↓
Tokenizer 与模型训练（Python / PyTorch）
   ↓
Q4 量化与模型包
   ↓
ESP32 C 语言运行时（板端推理）
   ↓
USB 逐 token 返回
   ↓
本地网页显示
```

**关键点**：

1. **不是"模型→压缩→塞进板子"，而是"从训练开始就让模型习惯量化"**（量化感知训练 QAT）
2. **不是"训练成功 = 板子能跑"，中间还有 C 语言运行时、固件、内存分工**——这套运行时覆盖：中文 Tokenizer / 模型包验证 / Q4 矩阵计算 / int8 激活 / Transformer 前向 / KV cache / 逐 token 生成 / 结束判断 / UTF-8 安全输出
3. **不是"电脑代替板子回答"，电脑只做 USB 传输和显示**——这保证测到的是板上模型的真实能力

## 四、内存分工（学员问"Flash/PSRAM/SRAM 怎么用"）

| 存储 | 特点 | 放什么 |
|------|------|--------|
| **Flash**（16 MB） | 大、只读、可内存映射 | 大量只读权重 |
| **PSRAM**（8 MB） | 中等容量 | 中间状态、临时缓冲 |
| **内部 SRAM**（小、512 KB TCM） | 最快 | 当前计算热点、控制结构、小型高频缓冲 |

**金句**：
> 模型能否稳定运行，不只取决于总大小，还取决于**每一类数据被放在哪里、活多久**。

## 五、关键技术概念速查

| 术语 | 一句话解释 | 类比 |
|------|-----------|------|
| **端侧模型** | 直接在设备上跑的模型，不依赖云端 | 板上的本地大脑 |
| **Tokenizer** | 把文字切成 token 并映射成整数 ID 的工具 | 中文→数字的转换器 |
| **token** | 切分后的最小单位 | 文字的"积木块" |
| **Decoder-only Transformer** | 只用解码器部分，按 token 顺序生成 | 一个 token 接一个 token 写答案 |
| **Q4** | 用约 4 位表示一个权重 | 精度换体积的压缩术 |
| **int8 激活** | 用 8 位整数表示中间值 | 计算过程的"低精度表达" |
| **量化感知训练 (QAT)** | 训练时同时观察 FP32/Q4/部署近似三条路径 | 训练时就让模型习惯低精度 |
| **teacher forcing** | 训练时给模型看前面对的答案 token | 给学生对照标准答案 |
| **AdamW** | 一种优化器，沿减小损失方向更新参数 | 模型学习的"导航仪" |
| **反向传播** | 找出每个参数对错误的贡献 | 追溯责任到每个权重 |
| **KV cache** | 缓存已算过的注意力结果，避免重算 | 笔记本上记得的中间步骤 |
| **RoPE** | 表示 token 相对位置的编码 | 给 token 加位置标签 |
| **SwiGLU** | 一种前馈网络结构 | 提升有限参数的表达能力 |
| **PLE（Per-Layer Embeddings）** | 每一层自己的辅助记忆表 | 不同层拿不同补充信息 |

## 六、训练→板端验证的"四套数据隔离"

| 数据集合 | 它答的问题 |
|---------|-----------|
| 训练集 | 模型怎样更新参数 |
| 选择集（480 条） | 七轮中哪一轮值得继续检查 |
| 独立审计集（480 条） | 是否只适应了选择集 |
| 公开验证集（1,146 条） | 最终统一观察完整回答 + 量化一致性 + 语义分组表现 |

> 学员问"为什么有这么多测试集"→ 一句话答：**避免"训练看着对、实际跑偏"**。

## 七、量化感知训练三条路径（学员问"怎么压小的"）

| 路径 | 用途 |
|------|------|
| **高精度路径** | 用 FP32 观察模型是否真的学会 |
| **Q4 权重路径** | 让模型提前适应低比特权重的误差 |
| **部署近似路径** | 用 Q4 权重 + int8 激活，尽量靠近板端真实计算 |

> 关键：**不是训练完再压缩**，而是**训练时同时观察三条路径**，这样模型"学会"的知识不会在量化时崩掉。

**额外安全设计**：正确答案与错误答案之间留 **0.5 分** 的间隔，避免"刚好领先"被量化误差翻转。

## 八、迁移到别的板/产品时需要重新设计的四部分

> 这段是讲义最有"方法论价值"的部分，志愿者反复用：

1. **知识边界**：设备必须知道什么，明确不处理什么
2. **训练数据**：把可靠事实扩展成真实问法 + 语义对照 + 可检查答案
3. **模型预算**：根据 Flash / PSRAM / 速度 / 任务复杂度决定词表、层数、宽度、上下文
4. **部署链路**：让 Python、导出工具、C 运行时、固件、真板测试遵守同一套格式与数值规则

**可复用闭环**：

> 先限定需求 → 整理知识 → 用可检查的数据从随机参数开始训练 → 训练阶段考虑量化 → 用相互隔离的数据评测 → 同一套 Tokenizer/模型/数值规则搬到芯片上验证

## 九、学员最可能问的 12 个问题

### 概念理解类

1. **"端侧模型和云端 API 到底选哪个？"**
   → 反应快+可断网+数据不出设备=端侧；模型大+能力强=云端。这块板选端侧是因为隐私、断网场景、响应路径短。

2. **"板子内存这么小，怎么塞下模型？"**
   → 不是把大模型压小，而是**先限定任务边界**，再按边界设计小模型；加上 **Q4 量化**把权重压到 4.14 MiB。

3. **"为什么要从随机参数开始训练，不能用预训练模型吗？"**
   → 这块板资源有限、任务边界窄（只答 EasyInput 问题）。预训练模型带着大量无关知识反而浪费空间。从随机开始+专用数据更高效。

### 工程实现类

4. **"Python 训练好的模型怎么搬到 C 语言的板子上？"**
   → 走完整链路：Python 训练 → 导出 Q4 权重 → 打包成"模型包"（含 Tokenizer+词表+权重+形状+SHA-256）→ 板端 C 运行时读取。

5. **"模型包怎么验证不是坏的？"**
   → 训练、导出、固件、运行时**四环节都核对 SHA-256**，四个一致才允许继续工作。

6. **"板上推理用什么硬件加速？"**
   → ESP32-S3 有**向量指令**（vector instructions）可加速神经网络/信号处理，ESP-DSP 和 ESP-NN 库会用上。

### 性能指标类

7. **"真板跑一个回答要多久？"**
   → 首 token 123–473 ms，完整 1.5–2.25 秒。

8. **"模型占用多少内存？"**
   → 模型包 4.14 MiB；加载后 PSRAM 剩约 5.42 MB。

9. **"为什么是 4.14 MiB 不是更小？"**
   → 已经包含 Tokenizer + 输出词表映射 + Q4 权重 + 张量形状 + SHA-256 校验。Q4 权重主体只有 3.86 MiB。

### 训练数据类

10. **"5,920 条数据够吗？"**
    → 数据增加的是**问法、对照和表达路径**，不是未经核验的知识。55 条原子事实够覆盖任务，5,920 条是把每条事实的不同问法、对照、风格铺满。

11. **"为什么留 0.5 分的安全间隔？"**
    → 避免量化误差翻转正确答案。"正确答案 10.01、错误答案 10.00"看似对，但量化稍微一变就翻车；留 0.5 分就是留出安全空间。

### 迁移复用类

12. **"我想做个自己的端侧 AI 产品，要重做哪些？"**
    → 看 §八 四个部分：知识边界 / 训练数据 / 模型预算 / 部署链路。最关键的是**先限定需求**，再考虑技术。

## 十二、本卡核心心法（一句话背下来）

> **小芯片上的模型能力，最终由任务边界、数据、模型结构、训练目标和部署环境共同决定。**

副心法：
- 不是"大模型压小"，而是**先限定边界再设计小模型**
- 不是"训练完再压缩"，而是**训练时就考虑量化（QAT）**
- 不是"训练成功就能跑"，中间还有**C 语言运行时 + 模型包 + 内存分工**这套工程链
- 不是"电脑替代板子"，**电脑只做传输显示**——保证测到的是板上真实能力
- 迁移时重做四部分：**知识边界 / 训练数据 / 模型预算 / 部署链路**
